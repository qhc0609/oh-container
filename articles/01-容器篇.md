# 01｜我在这台鸿蒙手机上从零写了个容器，然后把 Claude Code 跑了进去

> 系列第一篇。全过程可复制，命令都能直接粘。
> 代码在 GitHub：`qhc0609/oh-container`

---

先说结果。

手机 USB 插在电脑上，PowerShell 里敲一行 `hdc shell`，落在根目录 `/`，然后敲 `claude`。

两秒后，屏幕上出现 Claude Code 的界面。我问它"你在哪"，它回答：

```
我的模型名为 deepseek-flash，运行在 Linux（5.10.79，bash shell）环境下，工作目录为 /work。
```

模型是 DeepSeek V4.1 Flash，跑在我自己的 key 上。宿主机是一台鸿蒙手机。

这事听起来不难，做起来处处是墙。这篇讲第一段：**容器**。

---

## 一、为什么不能直接装

第一反应肯定是：手机上装个 Termux 不就完了。

鸿蒙不行。OpenHarmony 不是 Android，没有 `/system/bin/sh` 之外的包管理，没有 apt，没有 Termux 的生态。你能用的只有系统自带的那点 toybox。

第二个反应：装 Docker。

也不行。不是"没装"，是**内核编译时就没开**。Docker 依赖 PID namespace 和 cgroup，这台设备上：

```sh
$ ls /proc/self/ns/
cgroup  ipc  mnt  net  time  user  uts
```

没有 `pid`。

```sh
$ unshare -p true
unshare: unshare failed: Invalid argument
```

`EINVAL`。这不是权限问题，不是 SELinux 拦的（这台设备 SELinux 是 Permissive，`enforce=0`），是内核里压根没这个功能。user namespace 同理。

所以别指望 Docker、runc、podman、LXC。**这条路是死的，早点认。**

---

## 二、先摸清设备

我这台的参数，你手上那台大概率差不多：

| 项 | 值 |
|---|---|
| OpenHarmony | `OpenHarmony-4.0.10.13`（API 10） |
| 型号 | TaiHang2102 |
| 内核 | Linux 5.10.79 aarch64 |
| CPU | Cortex-A55 |
| SELinux | Permissive |
| hdc | 3.2.0f |

自己查：

```powershell
hdc shell param get const.ohos.fullname
hdc shell param get const.ohos.apiversion
hdc shell uname -a
hdc shell cat /sys/fs/selinux/enforce
```

重点看三件事。

**第一，`hdc shell` 进去是不是 root。**

```sh
$ id -u
0

$ grep CapEff /proc/self/status
CapEff:	000001ffffffffff
```

全 capability，`Seccomp: 0`。也就是说这台设备对你是完全敞开的——能挂载、能 chroot、能改路由。没有这个前提，后面的活全都干不了。

**第二，`/data` 能不能执行二进制。**

```sh
$ mount | grep ' /data '
/dev/block/dm-6 on /data type f2fs (rw,nodev,nosuid,...)
```

`nodev,nosuid`，但**没有 noexec**。所以 `/data` 下放的可执行文件能跑。

顺手看一眼 `/storage`：

```sh
$ mount | grep ' /storage '
... (rw,nosuid,nodev,noexec,...)
```

带 `noexec`。**rootfs 千万别放 `/storage`**，放进去所有二进制都跑不起来，报 `Permission denied`，你会以为是权限没给对，其实是挂载参数。

**第三，系统自带了什么。**

```sh
$ for c in chroot pivot_root unshare nsenter busybox tar; do printf '%-12s %s\n' $c "$(command -v $c)"; done
chroot       /system/bin/chroot
pivot_root   /system/bin/pivot_root
unshare      /system/bin/unshare
nsenter      /system/bin/nsenter
busybox      /system/bin/busybox
tar          /system/bin/tar
```

`chroot`、`unshare`、`busybox` 全在。这就是全部的原料，够用了。

## 三、namespace 到底能用哪几个

这是整个方案的地基，必须实测，不能猜。

```sh
for ns in mnt uts ipc net pid user; do
  [ -e /proc/self/ns/$ns ] && echo "$ns 可用" || echo "$ns 不可用"
done
```

结果：

| namespace | 状态 | 能干什么 |
|---|---|---|
| mount (`mnt`) | 可用 | 容器里的挂载点宿主看不见 |
| uts | 可用 | 容器能有自己的 hostname |
| ipc | 可用 | 独立共享内存 / 信号量 |
| net | 可用 | 能开，但**本方案不开**，容器直接用宿主网络 |
| **pid** | **不可用** | 没有 PID 1，进程列表和宿主共享 |
| **user** | **不可用** | 不能 rootless，容器内 root 就是宿主 root |

结论很清楚了：

**这是一个「mount + uts + ipc 隔离 + chroot 切根」的容器，不是 Docker。**

它没有 PID 隔离。你在容器里敲 `ps`，看到的是整台手机的进程。它也不能做 init 回收，容器里的孤儿进程会被宿主的 init 收养。

想清楚这一点，后面所有设计就顺了。

我把这个探测写成脚本了，换设备直接跑：`scripts/check-namespace.sh`。

## 四、rootfs 从哪来

容器的"根"得是个真的 Linux 文件系统。我选 Alpine。

理由很简单：小。官方 minirootfs 压缩包 3MB 左右，解压 8MB，`apk` 生态完整，musl 静态链接的二进制在 ARM64 上跑得很干净。

```sh
# 在设备上操作，注意路径必须在 /data 下（/storage 是 noexec）
mkdir -p /data/ohc/rootfs/claude /data/local/tmp/dl
cd /data/local/tmp/dl

curl -LO https://dl-cdn.alpinelinux.org/alpine/v3.21/releases/aarch64/alpine-minirootfs-3.21.3-aarch64.tar.gz

tar -xzf alpine-minirootfs-3.21.3-aarch64.tar.gz -C /data/ohc/rootfs/claude
```

到这里，`/data/ohc/rootfs/claude` 就是一个能跑的 Alpine 了。先验证一下：

```sh
chroot /data/ohc/rootfs/claude /bin/sh -c 'cat /etc/alpine-release'
# 3.21.3
```

能打出 `3.21.3`，地基就成了。

## 五、写运行时：核心其实只有 30 行

网上讲容器原理的文章都喜欢从 cgroup 讲起，讲半天 OCI 规范。我这台设备上 cgroup 有，PID namespace 没有，讲那些没用。

真正的核心就一件事：**在新 namespace 里挂好文件系统，然后 chroot，然后 exec。**

`bin/ohc` 的 `run` 子命令：

```sh
cmd_run() {
    _name="$1"; shift
    ensure_net                      # 补默认路由，见后面第六节
    exec unshare -m -u -i "$OHC_SELF" __inner "$_name" "$@"
}
```

三个参数：`-m` mount、`-u` uts、`-i` ipc。

**关键是这里没有 `-f`。**

`-f` 是 fork。加了 `-f`，`unshare` 会 fork 一个子进程去当"容器里的第一个进程"，父进程退出。听起来很对，但对交互式程序是灾难：子进程的 stdin/stdout 不是原来那个 TTY 了，`claude` 一起来就报 `not a terminal`，或者干脆卡死。

不加 `-f`，`unshare` 直接 `exec` 目标命令，**进程号不变，stdin/stdout 原样保留，TTY 还是那个 TTY**。

反正没有 PID namespace，也不需要谁来当 PID 1。这个"缺陷"在这里反而成了便利。

然后是 `__inner`，真正干活的地方：

```sh
cmd_inner() {
    _name="$1"; shift
    _rootfs="$OHC_ROOT/rootfs/$_name"

    # 1. 独立 hostname（已经在新 uts ns 里了，改不到宿主）
    hostname "$_name"

    # 2. 挂载树私有化，防止容器里的挂载传播回宿主
    mount --make-rprivate /

    # 3. 挂文件系统
    mount -t proc proc   "$_rootfs/proc"
    mount --bind /sys    "$_rootfs/sys"
    mount --rbind /dev   "$_rootfs/dev"      # rbind！见下面解释
    mount -t tmpfs tmpfs "$_rootfs/tmp"

    # 4. 工作目录：宿主 /data/ohc/workspace -> 容器 /work
    mount --bind "$OHC_ROOT/workspace" "$_rootfs/work"

    # 5. 加载环境变量（关键：set -a）
    set -a; . "$OHC_ROOT/containers/$_name/env"; set +a
    export HOME=/root

    # 6. 切根执行
    exec chroot "$_rootfs" /bin/sh -c 'cd "$1" 2>/dev/null || cd /; shift; exec "$@"' \
        ohc /work "$@"
}
```

四个地方值得单独说。

**`--rbind` 而不是 `--bind`。**

`bind` 只挂一层，`/dev/pts` 是 `/dev` 下面的子挂载，不会被带进来。结果就是容器里没有 `/dev/pts/0`，`claude` 一启动就崩。用 `rbind` 递归挂，`pts` 跟着进来，TTY 就有了。

**`mount --make-rprivate /`。**

不写这一行，容器里做任何挂载都可能传播回宿主。轻则宿主的 `/proc` 被覆盖，重则整机卡死要重启。这一行是保命的。

**`set -a`。**

这个坑我卡了整整两个小时。

`source env` 只是把变量变成当前 shell 的局部变量。`exec` 出去的新进程能继承的只有**导出的**变量。没 `set -a` 的话，`ANTHROPIC_AUTH_TOKEN` 在 shell 里明明有值，`claude` 就是看不见，表现是：

```
Not logged in · Please run /login
```

你会以为是 key 错了，去重新生成 key、重新配，配八遍都一样。其实就少了一行 `set -a`。

**`HOME` 必须强制成 `/root`。**

`hdc shell` 这个环境里 `HOME=/`。这个值会一路继承进容器。于是 `claude` 把配置写到 `/.claude.json`——根目录。

下次你从别的目录启动，它读的是 `$HOME/.claude.json`，也就是 `/.claude.json`，居然还能读到。但工作目录一换，信任状态就全乱，反复问你"是否信任这个目录"。

强制 `export HOME=/root` 之后，一切正常。

## 六、那个让人怀疑人生的网络问题

容器起来了，`curl https://api.deepseek.com` 却卡住不动。DNS 能解析，TCP 出不去。

```sh
$ netstat -rn
Kernel IP routing table
Destination     Gateway         Genmask         Flags   MSS Window  irtt Iface
192.168.76.0    0.0.0.0         255.255.255.0   U         0 0          0 wlan0
```

**只有链路路由，没有默认路由。**

`192.168.76.0/24` 是本地网段，所以能 ping 通路由器。但目标地址不在这个网段时，内核不知道往哪送，直接丢掉。

补一条：

```sh
route add default gw 192.168.76.15 dev wlan0
```

立刻通了。

这个毛病在 OpenHarmony 上不是偶发，是常态——WiFi 连上了、DHCP 拿到地址了，默认路由就是没写进去。所以我把它做成了幂等自检，每次 `ohc run` 都跑一遍：

```sh
ensure_net() {
    netstat -rn 2>/dev/null | grep -q '^0\.0\.0\.0' && return 0
    route add default gw "${OHC_GATEWAY:-192.168.76.15}" dev "${OHC_IFACE:-wlan0}"
}
```

有就跳过，没有就补。网关地址可以用 `OHC_GATEWAY` 覆盖。

## 七、toybox 的两个脾气

写脚本的时候会撞上两件莫名其妙的事。

**第一，没有 awk。**

```sh
$ awk '{print $1}'
awk: inaccessible or not found
```

toybox 精简掉了。但 `busybox` 是完整的，里面有 awk。所以运行时里所有用到 awk 的地方都做了兜底：

```sh
_awk() { if command -v awk >/dev/null 2>&1; then awk "$@"; else busybox awk "$@"; fi; }
```

**第二，`grep` 读管道会报错。**

```sh
$ netstat -rn | grep '^0.0.0.0'
grep: (standard input): Invalid argument
```

不是没匹配到，是**报错**。toybox 的 grep 在处理管道输入时有个 bug。

绕法一样，退回 busybox：

```sh
_grep() { if command -v grep >/dev/null 2>&1; then busybox grep "$@"; else grep "$@"; fi; }
```

这两件事在任何文档里都查不到。你不实际在这台机器上写脚本，永远不会知道。

## 八、容器里到底装了什么

把 Node 和 claude 装进去之后，`/data/ohc/rootfs/claude` 的构成：

| 内容 | 版本 / 体积 |
|---|---|
| Alpine base | 3.21.3，约 8 MB |
| Node.js | v22.23.4，约 110 MB |
| npm | 10.9.1 |
| `@anthropic-ai/claude-code` | 2.1.316，约 300 MB |
| `opencode-ai` | 1.19.5，约 210 MB |
| ripgrep | 14.1.1 |
| bash | 5.2.37 |
| **rootfs 合计** | **839 MB** |

装的时候是一条命令的事，在容器里跑：

```sh
apk update
apk add --no-cache nodejs npm bash curl ca-certificates ripgrep libstdc++ gcompat git
npm install -g @anthropic-ai/claude-code
```

**这里省了 202MB。**

`opencode-ai` 这个 npm 包会同时装 glibc 和 musl 两份原生二进制，各 200MB 出头。Alpine 是 musl，glibc 那份永远用不上。删掉：

```sh
rm -rf /usr/local/lib/node_modules/opencode-ai/node_modules/opencode-linux-arm64.bak
```

删之前先确认剩下的那份还能跑：`opencode --version` 有输出就行。

还有一处：npm 的缓存会涨到 484MB。

```sh
npm cache clean --force
rm -rf /root/.npm
```

清完 rootfs 从 1.0G 掉到 839M。

## 九、目录长什么样

设备上最终是这样：

```
/data/ohc/
├── bin/
│   ├── ohc                  # 容器运行时，POSIX sh，约 10KB
│   ├── ohc-claude           # 启动 claude 的入口
│   ├── ohc-setkey           # 写 DeepSeek Key
│   └── ohc-verify           # 端到端自检
├── rootfs/claude/           # 就是上面那个 Alpine
├── containers/claude/env    # 环境变量（含 key，权限 600）
├── workspace/               # 容器内 /work 的实体，文件落这儿
└── logs/
```

`workspace` 这个设计很重要。它在 `/data` 下，重启不丢，而且被 bind 进容器当 `/work`。也就是说 **claude 在容器里改的文件，宿主上直接在 `/data/ohc/workspace` 能看到**。容器删了，代码还在。

## 到这里你有了什么

一个能在鸿蒙手机上跑的容器。能切根、能隔离挂载、有独立 hostname、有独立 IPC、有持久化工作目录。

它没有 PID 隔离，不能当多租户平台用。但**在自己手机上跑开发工具，完全够**。
