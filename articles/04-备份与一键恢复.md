# 04｜我亲手 rm -rf 了自己搭了三小时的环境，然后 56 秒把它救回来

> 系列第四篇。这篇讲备份和一键恢复。
> 代码：`qhc0609/oh-container`

---

前三篇搭起来的东西，全在 `/data` 里。

`/data` 是什么？是刷机、恢复出厂设置、清除数据会清空的那个分区。

也就是说：**手机一出问题，三小时的活全白干。**

而且不是"重跑一遍脚本"那么轻松。重装要联网——`apk add` 要下载 Node、npm 要下载 claude、opencode 那个包 400MB。手机 WiFi 慢的时候，四十分钟起步。如果刷完机还没连上 WiFi，你连第一步都做不了。

所以我做了个东西：**834MB 整包备份，56 秒一条命令还原，全程不联网。**

---

## 一、先想清楚要备份什么

最省事的想法是：备份配置文件就行了，反正程序能重装。

不行。理由上面说了：重装要联网、要四十分钟。

那备份 `bin/` 和 `containers/`？也不够。那只是运行时和配置，没有 rootfs 就是个空壳。

**真正的答案是整个 `/data/ohc` 加 PATH 入口。**

具体清单：

```
/data/ohc/                              ← 839MB，容器 + 两个 AI + 全部依赖
├── bin/                                运行时和工具脚本
├── rootfs/claude/                      Alpine + Node + claude + opencode + ripgrep
│   ├── root/.config/opencode/opencode.json
│   └── root/.local/share/opencode/auth.json    ← OpenCode 登录状态，很关键
├── containers/claude/env               ← DeepSeek key
└── workspace/                          你写的代码

/data/python/lib/python3.8/script/bin/claude     ← PATH 入口
/data/python/lib/python3.8/script/bin/opencode   ← PATH 入口
```

压缩完 834.7MB。解压出来 839MB（二进制压缩率不高，正常）。

**为什么 `auth.json` 特别重要？**

因为 OpenCode 的登录状态在里面。不备份它，恢复完还得重新走一遍认证流程——而那个流程在手机上很容易卡。备份了它，恢复完直接能用。

## 二、打包：先在设备上压，再拉回 PC

不要在 PC 上通过 `hdc` 一个个拉文件，几万个小文件会慢到崩溃。

正确做法：**在设备上压成一个包，然后把一个包拉回来。**

设备上的压缩命令：

```sh
cd /data
tar -czf /data/local/tmp/ohc-backup.tar.gz ohc python
```

`ohc` 和 `python` 是两个目录：`/data/ohc` 和 `/data/python`。后者的 `script/bin` 里放着 PATH 入口。

然后拉回 PC：

```powershell
hdc file send  # 反了，是 file recv
hdc file recv /data/local/tmp/ohc-backup.tar.gz .\ohc-backup.tar.gz
```

`file send` 是 PC→设备，`file recv` 是设备→PC。这个命名很容易搞反，我第一次就写错了，然后盯着报错看了半天。

实测：26 MB/s，834MB 拉 34 秒。

## 三、第一个坑：tar 不打包 socket 文件

第一次打包，跑到一半挂了：

```
tar: unknown file type '140000'
```

`140000` 是八进制，转成十进制是 `49152`，也就是 `S_IFSOCK`——**Unix domain socket**。

`tar` 不支持 socket 文件。

哪来的 socket？查一下：

```sh
$ find /data/ohc/rootfs/claude -type s
/data/ohc/rootfs/claude/data/local/tmp/cc-socks/xxx.sock
/data/ohc/rootfs/claude/data/local/tmp/cc-socks/yyy.sock
/data/ohc/rootfs/claude/data/local/tmp/cc-socks/zzz.sock
```

三个，在 `cc-socks` 目录里。是 claude 之前某次运行留下的，进程退了但 socket 文件没清。

这三个 socket 没有任何价值——它们是死文件，对应的进程早就不在了。

打包前删掉：

```sh
find /data/ohc/rootfs/claude -type s -delete
```

写进备份脚本，每次自动做。

> 如果你也遇到这个错，别去改 tar 参数，`tar` 就是不支持。删掉那些 socket 文件，或者用 `--exclude` 跳过整个目录。

## 四、第二个坑：`/tmp` 是只读的

第一次写备份脚本，习惯性把文件列表写到 `/tmp`：

```sh
find /data/ohc -type f > /tmp/tarlist.txt
```

报错：

```
can't create /tmp/tarlist.txt: Read-only file system
```

在 OpenHarmony 上，**宿主机的 `/tmp` 是只读挂载**。

这个和普通 Linux 完全不一样。在 Linux 上 `/tmp` 永远可写，我根本没想过要检查。

改用 `/data/local/tmp`。这个目录可写，而且是设备上约定俗成的临时目录。

```sh
find /data/ohc -type f > /data/local/tmp/tarlist.txt
```

一个小细节，卡了二十分钟。

## 五、第三个坑：PowerShell 5.1 会把中文变成问号

这个坑最阴，因为它不报错。

`restore.ps1` 写好了，跑起来，设备端输出是这样的：

```
?????????
```

我一开始以为是控制台编码问题，改了 `chcp 65001`，没用。

真正的原因：

**PowerShell 5.1 读 `.ps1` 文件时，如果没有 BOM，它按系统 ANSI 代码页（中文 Windows 是 GBK）解码。而文件实际是 UTF-8。**

于是所有中文字符串在解析阶段就已经错了。不是显示问题，是**内存里的字符串本身就是乱码**。

第一次跑的时候报的是这个：

```
字符串缺少终止符: "。
```

因为中文字符被错误解码后，某个字节恰好被当成了引号，整个字符串的边界就乱了。

**修法：保存成 UTF-8 with BOM。**

```powershell
$content = Get-Content -Raw -Encoding UTF8 $path
[System.IO.File]::WriteAllText($path, $content, (New-Object System.Text.UTF8Encoding($true)))
```

`$true` 就是"写 BOM"。

改完立刻能跑。

**怎么验证一个 `.ps1` 有没有 BOM？**

```powershell
$bytes = [System.IO.File]::ReadAllBytes($path)[0..2]
if ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
    "有 BOM"
} else {
    "没 BOM，会出问题"
}
```

## 六、第四个坑：设备端脚本里的中文会变问号

解决了 `.ps1` 的编码，又撞上新的。

`restore.ps1` 里有一段"设备端脚本"，是要推到手机上执行的：

```powershell
$devScript = @'
#!/bin/sh
echo "开始解压"
tar -xzf "$PKG"
'@
Set-Content -Path $devScriptPath -Value $devScript -Encoding ASCII
```

用 `-Encoding ASCII` 是因为设备上的 shell 对编码敏感，ASCII 最安全。

但 ASCII 编码器**会把所有非 ASCII 字符替换成 `?`**。

结果设备上执行的是：

```sh
echo "????"
```

我一开始还用它做验证——让 claude 回复一个中文标记 `恢复成功`，然后脚本里 `if ($out -match '恢复成功')`。结果 claude 收到的提示词是 `????`，它老老实实回复了 `????`，然后脚本判断失败，报"验证不通过"。

查了半小时才发现是提示词在传输过程中就已经烂了。

**修法：设备端脚本全部用英文。**

```powershell
$devScript = @'
#!/bin/sh
set -e
PKG=/data/local/tmp/ohc-backup.tar.gz
[ -f "$PKG" ] || { echo "NO_PACKAGE"; exit 1; }
echo "--- extracting ---"
cd /data && tar -xzf "$PKG"
echo "EXTRACT_OK"
'@
```

验证标记也改成 `RESTORE_OK`、`EXTRACT_OK` 这种纯 ASCII。

这个原则记住就行：**跨编码边界的时候，只用 ASCII 做协议标记。** 中文留给人类看的地方。

## 七、第五个坑：控制台乱码

PC 端 PowerShell 输出中文，显示成 `锟斤拷`。

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

放在脚本开头。这样 `hdc shell` 回传的 UTF-8 字节能被正确显示。

不设也能跑，就是日志看着难受。

## 八、恢复脚本长什么样

`backup/restore.ps1`，九步：

**1. 找 hdc**

三个常见路径依次试，最后退回 `Get-Command hdc`。

**2. 核对 SHA256**

```powershell
$expect = ((Get-Content $sumFile -Raw).Trim() -split '\s+')[0].ToUpper()
$actual = (Get-FileHash -Path $Archive -Algorithm SHA256).Hash.ToUpper()
if ($expect -ne $actual) { Fail "校验失败，备份包可能损坏" }
```

834MB 的包，传网盘、拷 U 盘、放久了，都可能坏。坏包的后果是解压到一半失败，留下一个残缺的 `/data/ohc`，比没有更难排查。

**先校验，再动手。**

**3. 检查设备**

```powershell
$targets = (& $Hdc list targets 2>&1) | Where-Object {
    $_ -and $_ -notmatch '\[Empty\]' -and $_ -notmatch 'Unauthorized'
}
```

`Unauthorized` 是刷机后最常见状态——手机上要点一下"允许调试"。不处理的话脚本会一直等。

**4. 检查 `/data/ohc` 是否已存在**

```powershell
$probe = (& $Hdc shell "if [ -d /data/ohc ]; then echo YES; else echo NO; fi" 2>&1) -join ' '
if ($probe -match 'YES') {
    if (-not $Force) { Fail "设备上已存在 /data/ohc。确认覆盖请加 -Force" }
}
```

这一步是保护。你要是手滑在有环境的时候跑了一遍恢复，没这个检查就直接覆盖了。

**5. 推送**

```powershell
& $Hdc file send $Archive /data/local/tmp/ohc-backup.tar.gz
```

34 秒。

**6. 下发设备端脚本**

写临时文件 → `file send` → `chmod 755`。

为什么不在 PowerShell 里拼一长串 `hdc shell "..."`？因为引号嵌套会疯。三层引号（PowerShell 一层、hdc 一层、sh 一层）里任何一个特殊字符都能让命令变形。写成文件推过去，一次干净。

**7. 执行解压**

```powershell
$out = (& $Hdc shell "/data/local/tmp/ohc-restore-device.sh test" 2>&1) -join "`n"
if ($out -notmatch 'EXTRACT_OK') { Fail "解压失败，见上方输出" }
```

22 秒。

**8. 修权限**

`tar` 解压会保留权限，但 `hdc file send` 推过去的文件权限是固定的。所以解压后统一 `chmod`：

```sh
chmod 755 /data/ohc/bin/ohc /data/ohc/bin/ohc-claude /data/ohc/bin/ohc-setkey
chmod 755 /data/ohc/bin/ohc-verify
chmod 755 /data/python/lib/python3.8/script/bin/claude
chmod 600 /data/ohc/containers/claude/env
```

漏掉 `chmod 755` 的后果：`claude` 在 PATH 里但执行报 `Permission denied`。看着像权限问题，其实是没给执行位。

**9. 验证**

```powershell
$which = (& $Hdc shell "command -v claude" 2>&1) -join ' '
if ($which -match 'claude') { Write-Ok "claude 在 PATH 中" }
```

然后真调一次：

```sh
claude -p "Reply with exactly this token and nothing else: RESTORE_OK"
```

输出里有 `RESTORE_OK` 才算真通。这一步会花掉一点点 token，不想花就加 `-NoTest`。

## 十一、环境变了怎么办

换了 API Key、升级了 claude、装了新工具——备份就过期了。

`backup/backup.ps1` 重新打包，一条命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\backup.ps1
```

它做四件事：设备上重新 `tar` → 拉回 PC → 重算 SHA256 写进 `SHA256SUMS.txt` → 清理设备临时文件。

我的建议：**每次环境有实质变化就跑一遍。** 反正一分钟的事。

---

## 十二、这个备份不能乱传

说三遍。

**包里是明文 API Key。**

`containers/claude/env` 里有你的 DeepSeek key，`auth.json` 里有你的 OpenCode key。整个包是普通 tar.gz，没有任何加密。

所以：

- 不要传网盘
- 不要传 GitHub（我在 `.gitignore` 里排除了）
- 不要发给别人
- 不要放在共享目录

想加密的话，套一层：

```powershell
openssl enc -aes-256-cbc -pbkdf2 -in ohc-backup.tar.gz -out ohc-backup.tar.gz.enc
```

恢复时先解开再跑 `restore.ps1`。

我在 GitHub 仓库里**没有**放这个 834MB 的包，只放了脚本。你要用就自己打一个——反正 `backup.ps1` 一键就出来了，而且里面是你的 key，本来也不该用别人的。

## 十三、手动兜底

脚本万一出问题，记住这几条命令就能手救：

```powershell
$hdc = "C:\Tools\HarmonyOS\toolchains\hdc.exe"

& $hdc list targets
& $hdc file send .\ohc-backup.tar.gz /data/local/tmp/ohc-backup.tar.gz

```

## 系列收尾

四篇下来，完整的链路是：

1. **容器** —— 从零写一个运行时，绕开内核缺失的 PID namespace
2. **claude** —— 接 DeepSeek 官方 Anthropic 端点，花自己的钱，工具链完整
3. **opencode** —— 接 OpenCode Zen 免费网关，不花钱，有速率限制
4. **备份** —— 834MB 整包，56 秒还原，不联网

一台鸿蒙手机，两个 AI 编程助手，一个能扛住刷机的备份。
